# 发布签名证书指纹
#
# ## 这个文件存在的唯一目的：让「签名不一致」变成可检测的，而不是靠记性
#
# Android 拒绝安装签名不同的更新。发布密钥一旦被**误重新生成**，
# 后果是所有已安装的用户都无法升级——只能卸载重装，数据丢失。
# 而这个错误在发版当天是发现不了的：包能装、能跑，只是下一次就装不上。
#
# 所以在发版前用 `scripts\verify-signing.ps1` 核对本地 keystore
# 与本文件的指纹是否一致。不一致就停下来，别发。
#
# ## 什么时候可以改这个文件
# **只有**在以下两种情况：
# 1. 首次建立发布签名（本文件是为此而生的）
# 2. 确认旧密钥已彻底丢失、且已接受「所有用户必须重装」之后
#    ——此时 applicationId 也应该一并改掉，避免新旧包互相覆盖出错
#
# 指纹是公开信息（它就印在每个 APK 里），写进仓库没有安全顾虑。
# 仓库里**绝对不能**出现的是密钥本体与口令。
#
# 格式：冒号分隔的大写十六进制，apksigner 的原样输出。
EA:AA:5A:67:11:DB:A9:D3:B5:ED:F9:90:EF:FF:61:B1:C4:91:2A:FF:25:A8:F8:34:A7:4C:8E:97:C4:EE:55:C9
